# 声明式构建与应用生命周期

## 核心结论

`DesktopApp` 持续管理窗口和事件循环；传给 `run` 的构建函数根据当前状态描述“现在应该显示什么”。状态变化时，相关声明可能再次执行。

因此，构建函数必须轻量、可重复。业务事实不能依赖临时组件实例，一次性副作用也不能混入普通界面声明。

## 一次更新发生什么

1. 输入事件、后台投递或动画改变状态。
2. CUI 根据实际的状态读取记录，找出受影响的声明作用域。
3. 相关作用域重新构建；需要时继续测量和布局。
4. 本帧使用稳定后的新组件树绘制。
5. 没有输入、状态变化或动画时，应用阻塞等待，不持续空转。

这意味着“声明式”不等于“每帧重建整棵树”。普通容器的构建块会自动进入增量依赖图；稳定分支可以跳过构建、布局或绘制工作。应用无需普遍添加缓存包装器。

## 构建函数中可以做什么

适合放入构建函数：

- 读取状态和便宜的派生值。
- 根据状态选择组件。
- 设置布局、样式和事件回调。
- 用 `remember` 或 `rememberState` 取得已经由框架持有的值。
- 声明 `mountEffect` 或 `lifecycleEffect`，把真正的创建和清理交给提交阶段。

不适合放入构建函数：

- 读取大文件、访问网络或执行耗时计算。
- 每次启动一个后台任务。
- 追加全局集合、写日志计数或修改业务状态。
- 手工调用组件的 `measure`、`layout`、`draw` 或 `handle`。
- 创建没有明确关闭位置的长期资源。

一个简单判断是：如果同一段代码连续执行两次会改变业务结果，它就不应作为普通构建逻辑。

## 数据放在哪里

| 数据 | 推荐所有者 |
|---|---|
| 用户输入、选择、业务记录 | 页面模型、`State` 或 Store |
| 只服务固定声明位置的展开、临时选择 | `rememberState` |
| 可由事实计算的标题、计数、有效性 | 普通计算或 `DerivedState` |
| 控制器、动画器、格式化器 | 外部模型或 `remember` |
| 文件、观察订阅等可关闭资源 | `DesktopApp.manage`、`mountEffect` 或 `lifecycleEffect` |

组件实例只表示本次构建的界面值。实例字段可以保存构造参数和当前布局矩形，但不应成为业务事实的唯一存储位置。

## 身份与动态结构

无键的 `remember`、`rememberState` 和生命周期 effect 按声明位置识别。固定、无条件的结构最适合这种形式。

条件分支、循环和可重排列表会改变位置。此时应使用稳定业务键，通过 `Keyed`、`ForEach` 或带 `key` 的控件明确身份。键应在同级范围内唯一、非空，并在业务对象不变时保持不变。

不要用数组下标表示可重排项目，也不要用随机值或会随语言变化的显示文字作为键。

## 事件和同帧一致性

按钮点击、文本输入和键盘操作都在事件事务中运行。回调修改 `State` 后，CUI 会在最终绘制前完成必要的重建和布局，因此画面不会混合事件前后的状态。

只修改普通 `var` 不会产生状态失效信号。即使下一帧偶然重新构建，当前组件仍可能保存旧文字或旧可用状态。凡是会改变可见结果、命中区域或交互能力的持久值，都应进入可观察状态。

## 副作用与资源

用户动作可以发起文件、网络或后台工作，但耗时部分不应阻塞 UI 线程。工作线程只产生普通结果，再通过 `DesktopApp.post` 回到 UI 线程更新状态。

需要关闭的资源必须有明确所有者：

- 与整个应用同寿命：交给 `DesktopApp.manage`。
- 与某个声明位置同寿命：使用 `mountEffect`。
- 配置版本变化时需要替换：使用 `lifecycleEffect`。

effect 的创建在构建成功后提交；构建失败不会用半成品替换已生效资源。卸载或应用关闭时，框架执行清理。

## 按需渲染

动画和轮询不能假设 `draw` 会永久调用。需要下一帧时使用 `Animator`、`Spring`、`Pulse`、`FrameHandler` 或 `UiContext.requestFrame`；动画静止后应停止请求。

只在底层诊断或特殊兼容场景使用 `RetainedSubtree`。常规界面已经具备自动依赖跟踪和增量执行，不需要手工给每个区域增加保留边界。

## 常见错误

- 把 `run` 的构建函数当作只执行一次的初始化函数。
- 在构建过程中启动任务或写业务状态。
- 把用户输入放在组件临时字段中。
- 动态列表沿用位置身份，重排后状态跟错项目。
- 从后台线程直接修改 UI 状态。
- 动画结束后仍无条件请求下一帧。
