# 2026-09-07 第二轮质量加固

本轮围绕异常退出、资源清理、输入恢复、状态通知和外部数值边界检视。修改前 CUI 920 项、CangjieSDL 191 项测试通过；新增用例复现了既有测试未覆盖的失败路径。上一轮字体、启动、滚动、增量绘制和后台任务场景继续参与验收。

## 修复内容

| 问题 | 修复与验收重点 |
|---|---|
| 运行异常被关停异常覆盖，多个清理错误丢失 | 停止投递、受管资源、无障碍桥、状态／effect 和原生窗口逐阶段尝试清理；保留原始异常对象及发生顺序 |
| effect 构建回滚、观察者通知和派生订阅清理丢失后续错误 | 汇总各个失败，继续处理后续通知／清理；失败资源的状态查询不在 catch 中重复执行，避免跳过其余资源 |
| 模型提交后通知与 effect 交付同时失败，只留下前者 | 保留两阶段错误，模型仍只提交一次、effect 仍只交付一次，失败后可继续派发与绘制 |
| 鼠标释放处理器抛错后遗留按压／拖拽 | 原始事件和带元数据事件共用收尾路径；收尾也失败时与处理器异常一并保留 |
| 测试宿主 reset 清理失败后仍残留交互状态 | 清理失败仍恢复焦点、按压、拖拽、浮层、语义、输入锚点与帧状态，然后报告失败 |
| NaN／无穷字体或显示缩放产生无效几何 | 非有限缩放恢复 1.0；正常有限值继续使用原有最小值约束，重复无效输入不会反复失效环境 |
| 外部 NaN 滚动状态进入子项布局 | 布局前恢复到顶部；正／负无穷限制到末端／开头；共享滚轮函数也拒绝非有限增量 |
| 原生裁剪矩形右／下边界相加溢出 | 除坐标和宽高外，还校验右／下边界；拒绝输入后逻辑裁剪栈和原生渲染仍可继续使用 |

## 异常接口与兼容性

新增 [`UiAggregateException`](../../docs/api/cui/core/UiAggregateException.md)，从 `cui` 或 `cui.core` 导入。单个异常原样重抛；多个异常才使用聚合类型，`primary` 是最先发生的错误，`failures` 返回原始异常列表的副本。框架展开嵌套事务的聚合错误，保留每个原因及其堆栈。

原先只捕获复合失败中某个具体类型的调用方，应补充聚合类型分支。这是本轮明确的错误报告契约变化；已提交的模型不会因通知异常自动回滚，资源关闭失败也不代表已经成功释放。正常事件与状态通知路径仅在实际出现错误时分配异常收集器。

## 回归方式

- 单元／集成用例检查原始异常对象身份、失败顺序、输入／输出数组隔离、单异常兼容性、清理重试、后续观察者送达，以及失败后继续交互。
- `failure-recovery` 原生窗口场景覆盖首次绘制失败后隐藏窗口清理、受管资源与 effect 多重错误、鼠标释放失败、reset 失败与重建、状态事务及 EffectStore 交付失败后的恢复。
- `numeric-recovery` 原生窗口场景在直接／超采样两种路径，对比无效值恢复与正常值的实际 BMP；校验滚到底后的稳定性和整数裁剪拒绝后的画面一致性，每次比较零容差。
- 既有 planner 双页底线、字体与文本编辑、首帧、后台投递、公平性、异步关闭和保留／完整绘制场景重跑。

原始失败、修复后结果及验收索引位于 `target/dev/quality-2026-09-07-r2/`。本轮不覆盖 Linux／macOS 实机、完整屏幕阅读器、长期资源压力和最终安装包验收，相关发布任务保留在 todo 中。
