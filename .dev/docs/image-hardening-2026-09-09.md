# 图像链路复核与加固（2026-09-09）

本轮对上一轮静态图像升级涉及的解码、资源所有权、缓存、保留绘制、错误占位、原生状态和发布依赖进行了复核。保留静态图像范围；没有加入动画或 WebP/TIFF/AVIF 可选 DLL。

## 发现与修复

| 问题 | 触发条件与结果 | 修复及验证 |
|---|---|---|
| 新缓存条目被自己淘汰 | 旧条目均获得二次机会时，刚加载的纹理反而成为淘汰对象，可能返回已关闭资源或触发缓存不变量异常 | 淘汰过程始终保护本次新条目；用两个热条目和第三次入库复现 |
| 清空缓存后保留旧链表 | 活跃视图/快槽仍引用一个条目时，previous/next 可能拖住整代缓存元数据 | 清空时拆除双向链接；测试持有中间节点后清空 |
| 已淘汰失败图无法可靠刷新 | 失败图片的空绘制命令仍存活，但 invalidateImage 找不到缓存项便不通知观察者 | 显式失效始终通知；600 次其他加载后创建文件并刷新，仍无需重建即可更新尺寸与内容 |
| 缓存压力导致重复读取坏文件 | 存活 ImageView 的失败条目被全局缓存淘汰后，再绘制会重新访问磁盘；大备用图会加重此问题 | 视图保留本次失败解析，直到显式失效或解码策略改变；回归检查再次绘制的 miss 数不增加 |
| 透明度依赖纹理旧混合模式 | 不透明来源或设置为 None 的纹理忽略 opacity；后续修改纹理混合模式还会改变录制样式的结果 | textureStyled 独立使用标准 Alpha 混合，绘制后恢复原混合与采样模式；像素与状态断言覆盖 None/Add |
| 极端几何输入越过防线 | 有限 x、w 相加仍可能溢出；极大圆角在限制细分前转 Int64 会抛 OverflowException | 校验矩形边界，先在浮点域限制细分数量；验证顶点有界、索引合法，无需创建巨型 GPU 资源 |
| 录制与直接绘制的纹理检查不一致 | 失效纹理可能先被录入命令；外来纹理的错误延迟到结束录制 | 录制前校验资源，以相同 SdlException 拒绝失效/外来纹理 |
| 自定义错误绘制泄漏裁剪 | 回调增加内层裁剪后抛异常，单次 pop 无法恢复调用者的裁剪 | 错误占位先录制、成功且裁剪配对后才回放；用故障回调验证父裁剪保持不变 |
| 旧 BMP 保存可截断路径 | 含 NUL 的路径传入 C 字符串后可能写到前缀文件名 | saveBmp 与其他图像读写入口统一拒绝 NUL；检查 BMP/PNG/JPEG 保存均不产生前缀文件 |

另外，解码像素预算使用原生整数宽高计算，避免 Float32 元数据舍入；边界测试包含恰好 192 像素可接受、191 像素预算即使要求缩小也应在缩小前拒绝。

## 接口约定

- 存活视图的失败状态现在持续到 invalidateImage、clearImageCache 或 decodeOptions/decodeSize 变更；全局缓存淘汰不再引起重复失败解析。成功纹理仍服从缓存释放和渲染器生命周期。
- textureStyled 的合成语义固定为标准 Alpha，不继承纹理的特殊混合方式。原混合/采样值在 finally 中恢复；需要特殊混合时使用普通纹理绘制接口。
- errorPlaceholder 只发出可录制的绘制命令。不要在其中开始/结束场景、抓取画面、修改纹理状态或改写应用 State；回调异常仍传播，但不泄漏裁剪。
- Surface.create 创建 RGBA32；加载后的原生像素格式由解码器选择，像素读写辅助接口使用 RGBA 颜色。文件路径含 NUL 均属于 IllegalArgumentException。

[SDL_RenderGeometry 文档](https://wiki.libsdl.org/SDL3/SDL_RenderGeometry)说明颜色和 Alpha 调制来自顶点；[SDL_GetTextureBlendMode](https://wiki.libsdl.org/SDL3/SDL_GetTextureBlendMode)用于保存原混合状态。本次通过真实像素测试确认最终合成效果。

## 性能与检查边界

| 场景 | 加固前中位数 | 加固后中位数 |
|---|---:|---:|
| 稳定视图失败缓存 | 5 ns | 4 ns |
| 新建视图失败缓存 | 42.5 ns | 42 ns |
| Contain 百图网格 | 24.57 μs | 23.933 μs |
| Cover 百图网格 | 24.693 μs | 24.854 μs |

缓存场景各 54 次采样，网格场景各 42 次；原始范围与二进制 SHA-256 保存在 performance-delivery.json。前几轮波动数据也完整保留，未改写原始日志。

微基准为交替运行的加固前后二进制；网格为 100 张图、400×240、1× 超采样，计时不含 DesktopApp 事件/布局调度和窗口呈现等待。结果存在微秒/纳秒级波动，不能据此承诺所有负载严格零开销。正常图片继续复用纹理与网格；错误占位增加的录制只发生在自定义失败绘制路径。缓存淘汰后的失败重读通过 miss 计数回归验证已消除。

生产代码按仓库 cangjie-format.toml 格式化。外部 cjlint/cjfmt 的历史告警没有被隐藏：枚举成员与丢弃参数沿用现有命名约定；共享原子版本值保留在需要复用的作用域；ImageSource 的惰性空值回退有明确的参数校验语义；测试文件保留原有布局。相关内部异常契约已补全文档，未扩大全局豁免或关闭规则。

本次原生验证为 Windows x64。首次解码仍同步执行；位图缩小发生在完整解码后，像素预算不能限制解码器临时内存。SVG 是 SDL_image 静态子集。这些限制与使用方法见[图像指南](../../docs/guide/how-to/images.md)。

原始复现、修复后测试、基线比较和性能日志位于两仓库的 target/dev/image-hardening；发布报告为 GUI target/dev/release/windows-x86_64-delivery.json。
