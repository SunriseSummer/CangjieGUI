检查了画廊中全部 48 个示例，参考 booking、planner 的信息分区，重点更新 editor、notepad、notes、paint。

| 示例 | 界面变化 | 编码与行为加固 |

| editor | 写作空间页头、单一主要操作、纸面编辑区、紧凑菜单／视图设置／编辑命令、修改状态 | 稳定文档 key；命令使用当前 TextArea；移除无行为的打开动作和未实现的菜单快捷键提示；检查点派生 dirty |
| notepad | 文件名与修改标记、轻量工具栏、纸面、独立统计；长路径悬停可见 | 按需对话框帧订阅；工具栏粘贴保留选区及撤销；保存成功才标记干净；只有未保存修改才确认新建 |
| notes | 暖色主从布局、侧栏计数、文档内删除、空状态 | 按笔记区分编辑器身份；空列表禁用无效菜单；删除确认默认聚焦保留动作；固定侧栏采用 hug，避免参与空间平分 |

普通按钮的 `Theme.buttonSurface` 原先把主题阴影透明度强制改成 20，透明主题仍会出现浮起阴影。
现在透明度取主题值与 20 的较小值；默认主题外观保持原样。四个示例使用透明主题阴影和轻量按钮，
主要操作保留强调色，文档卡片通过显式表面保持层次。普通工具栏按钮继续使用默认交互样式，保留悬停、按压与焦点反馈。
新增测试覆盖阴影透明度为 0、12、28 的情况；未改变公开接口。

## 示例编写原则

1. 把“主要动作、次要命令、视图设置、状态”分开。不要让所有操作都拥有同等强烈的边框、颜色与阴影。
2. 字体使用 fp，空间使用 vp。工具栏自然测量、必要时用 FlowRow 换行；不能靠固定小高度获得紧凑效果。
3. 主题文件管理配色、表面与重复尺寸；视图负责组合，模型负责状态和业务动作。
4. 选区粘贴、剪切、撤销等使用当前编辑控件命令。应用替换文档是独立动作，必须维护身份、光标与锚点。
5. 复用标准控件的交互协议。色块可改变外观，但仍应支持键盘、语义名称、选中状态与取消按压。
6. 仅在工作存在时订阅帧。notepad 请求结束后移除订阅，避免空闲文本框因外围轮询不断参与帧处理。

## 功能边界

editor 的检查点、notes 的笔记仍只保存在当前会话中；notepad 才实际写文件。
notepad 的新建确认不代表已经实现所有打开／关闭场景的防丢失工作流。
paint 是线段画布教学示例，未新增笔迹文件格式、导出或绘画撤销功能。
这些边界在各示例 README 中说明，避免界面文案承诺未实现的能力。
