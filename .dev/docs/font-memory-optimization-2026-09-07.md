# 字体按需加载、仓颉迁移与资源优化

本轮移除了 CangjieSDL 的 `native/` 字体扩展及补丁 DLL 依赖。平台匹配、SFNT 元数据、变量字体视图、基线修正和文字图集由仓颉实现；底层 shaping、轮廓栅格化仍使用官方 SDL3_ttf 内置的 HarfBuzz／FreeType。数值字重、变量轴、命名实例、真实／合成样式及旧字体接口继续可用。

## 行为变化

- 启动、默认角色、按族名查询和查询失败都不再创建完整字体目录。应用文件优先，其后按需解析平台 UI 字体和有限后备；全部失败时明确报错。
- `Fonts.familyFaces(name)` 只查询指定字体族／角色／注册别名的字体面与轴。缺失名称也有有界缓存，避免逐帧重复访问系统。
- `Fonts.systemFamilyNames()`／`systemFonts()` 仍提供完整目录，但只有显式调用才加载。Windows 显式枚举同时覆盖注册表和 DirectWrite 的应用包文件字体，不能仅用注册表代替系统目录。
- fonts 示例启动只准备默认角色和定向查询的 Cascadia Code；“加载系统字体”按需提供全部选项，随后可刷新。字重滑杆步长为 25，设计轴步长为 1；公开 API 仍接受精确字重与轴坐标。
- 已有命名实例直接打开；其他坐标使用官方 `SDL_IOFromConstMem` 和小型 SFNT 视图。主体轮廓文件按只读映射共享，不为每个字重复制整个字库。
- 同一路径替换字体后，新旧存活会话按元数据身份隔离映射；最后一个使用者释放时关闭映射／流。字体图、度量、纹理和目录的失效规则保留。
- 字形和装饰共用校正后的布局；glyph 的行号直接采用公开 cluster 数据。装饰线查询使用有序索引，避免长文档按字形逐行遍历。

完整目录在本机仍为 **222 个字体族、575 个字体面／实例**。与迁移前逐文件、面号及所有缓存元数据字段比较：缺失 0、新增 0、字段差异 0。其中 21 个变量文件包含 170 个命名实例，连同基础面共 191 条有轴记录；11 条既有目录警告不变。

## 测量方法

沿用[迁移前评估](font-cost-assessment-2026-09-07.md)的 Windows 11、Core Ultra 7 268V、Arc 140V、32 GiB、仓颉 1.0.5／`-O2` 环境。进程绑定同一组性能核，串行运行，不与构建任务重叠；每例使用新进程，但**没有清空操作系统文件缓存**，不能称为冷磁盘启动。

启动各 5 次。字体实验室固定／三档／连续字重各 5 次；16 行混排矩阵共 16 类、每类 3 次。每次绘制 620 帧，稳态统计剔除前 20 帧，并单独检查首次切换开销。禁用 vsync，整帧耗时包括布局／绘制／提交；CPU 指整个进程的 CPU 时间。私有内存是进程 Private Bytes，包含仓颉堆、SDL、FreeType 和驱动分配，并非单独的字体缓存大小。

另将保存的旧二进制＋旧运行库与新二进制＋官方运行库交错运行：10 类场景 × 3 轮 × 2 版本，共 60 次。下方多行对照优先采用这组同时段结果，减少机器状态变化的影响。全部原始帧样本和失败／中间记录均保留，最终结果未使用早期字体不匹配的试跑数据。

## 启动结果

| 场景／指标 | 迁移前 | 本轮 |
| --- | ---: | ---: |
| 默认最小界面，到显示后的下一帧 | 856.6 ms | 198.6 ms |
| 显式指定同一默认字体文件 | 118.6 ms | 127.0 ms |
| 原样运行 fonts 示例，首次原生窗口可见 | 981.9 ms | 254.4 ms |
| fonts 首屏进程 CPU | 921.9 ms | 250.0 ms |
| fonts 首屏私有内存 | 168.9 MiB | 76.9 MiB |
| 显式枚举完整目录 | 780.7 ms | 632.9 ms |

fonts 首屏时间下降约 **74%**，首屏私有内存下降约 **54%**。最终 5 次首屏范围为 236.6～286.3 ms。指定文件的启动中位数增加约 8 ms，未出现原先整目录扫描带来的数百毫秒成本。

完整枚举仍有约 0.63 秒开销，主要来自平台目录访问；它不在默认启动或按名称选字的路径上。本机启用持久元数据缓存后为 632.1 ms，收益不明显，因此保持默认关闭，不为普通应用额外读写缓存文件。

## 运行结果与成本

实际 fonts 页面使用相同 Cascadia Code、相同窗口与 2.25 × 2.25 栅格比例。连续模式每帧传入 400～700 的整数权重，没有用示例滑杆的步长 25 替代压力输入。

| fonts 页面模式 | 整帧中位数，前 → 后 | P95，前 → 后 | CPU／帧，前 → 后 | 620 帧后私有内存，前 → 后 |
| --- | ---: | ---: | ---: | ---: |
| 固定 400 | 0.740 → 0.627 ms | 2.993 → 0.933 ms | 0.932 → 0.857 ms | 151.2 → 164.0 MiB |
| 400／600／700 | 0.696 → 0.636 ms | 2.933 → 0.915 ms | 0.958 → 0.857 ms | 159.8 → 169.7 MiB |
| 连续 400～700 | 5.892 → 0.891 ms | 6.993 → 1.852 ms | 6.502 → 1.260 ms | 205.6 → 192.4 MiB |

连续模式整帧下降约 **85%**、CPU 下降约 **81%**。固定和三档模式的整页强制重绘结束后，私有内存比旧版多约 10～13 MiB；不能宣称所有场景的进程内存都下降。此时字形图集实际只有 1～2 MiB，连续模式为 4 MiB；其余进程内存尚需专门的分配归因，不能直接当作字体泄漏。

交错测试的 16 行混排结果：

| 场景 | 整帧中位数，旧 → 新 | CPU／帧，旧 → 新 | 私有内存，旧 → 新 |
| --- | ---: | ---: | ---: |
| Cascadia 固定，1 倍采样 | 0.265 → 0.268 ms | 0.277 → 0.151 ms | 72.5 → 67.1 MiB |
| Cascadia 固定，2 倍采样 | 0.575 → 0.574 ms | 0.227 → 0.202 ms | 111.3 → 106.1 MiB |
| Noto 中文固定，2 倍采样 | 0.588 → 0.583 ms | 0.302 → 0.353 ms | 111.8 → 106.5 MiB |
| Cascadia 连续字重，1 倍采样 | 8.709 → 3.193 ms | 9.022 → 3.629 ms | 232.4 → 150.4 MiB |
| Cascadia 连续字重，2 倍采样 | 9.437 → 4.330 ms | 10.005 → 4.637 ms | 552.4 → 186.2 MiB |
| Noto 中文连续字重，1 倍采样 | 9.767 → 3.604 ms | 10.207 → 4.158 ms | 301.4 → 154.9 MiB |
| Noto 中文连续字重，2 倍采样 | 10.465 → 4.507 ms | 10.912 → 4.990 ms | 680.5 → 194.0 MiB |

固定文字整帧基本持平，连续变重的高分辨率压力场景私有内存下降约 **66%／71%**。完整矩阵中的 Bahnschrift 连续字宽从原基线约 10.06 ms 降到 3.29 ms（2 倍采样）。这些是整帧数据，不能当作单次字形绘制或单次设置轴的耗时。

首次为某个活动文件建立虚拟实例需要计算源文件校验和。这是一次性成本：1 倍采样的 Noto 中文场景，首次从默认 400 切到 401 的完整帧为 19.9 ms，旧版为 13.1 ms；后续任意权重复用源映射和校验和。静态字重及已有命名实例没有这项虚拟视图成本。需要严格帧预算的动画仍应提前准备所需字体，或限制更新频率。

## 资源边界与实现取舍

| 资源 | 上限／策略 |
| --- | --- |
| 缓存字体配置 | 24 个，原来 64 个；存活测量会话有独立生命周期 |
| 字形图集 | 每 Renderer 16 MiB，按页 LRU 淘汰；32768 条字形记录 |
| 整段文字纹理 | 256 块／16 MiB，保留斜体和旋转的整段 shaping 路径 |
| shaped-text | 每字体 512 KiB 估算预算 |
| 元数据缓存 | 8 MiB／512 文件；失败路径最多 512 项 |
| 虚拟字体私有映射 | 常见约 128 KiB／实例，上限 320 KiB；主体轮廓页共享 |
| 源文件映射 | 单文件不超过 1 GiB，最后使用者释放后关闭 |
| CPU Surface | 最多 16M 像素／64 MiB RGBA |
| 图集字形槽 | 含边缘不超过 2048 × 2048 |

上述独立预算不能直接相加当作整个进程的内存上限；FreeType 内部对象、驱动、应用状态及尚未关闭的会话另计。压力矩阵中图集达到 16 MiB 后持续淘汰，重绘像素保持一致，未通过无限增长换取帧速率。

SFNT 读取限制为单表 2 MiB、单文件元数据 8 MiB；名称和 fvar 坐标也有数量／字节限制，损坏或超限文件进入现有诊断／后备流程。支持可访问的 TTF／OTF／TTC／OTC 文件；私有内存、远程、多文件字体和非 SFNT 格式不由这一元数据／变量视图层支持。

开发中捕获过仓颉 IO 回调在强制 GC 下的原生栈遍历崩溃，最终实现已完全移除这类 IO 回调。内存流使用 SDL 自带回调；文字引擎回调只更新预分配的原生标记，布局构造和资源释放在回调返回后执行。没有禁用 GC 或删除压力用例。

## 验证与发布范围

- CangjieSDL：206 项测试通过；CUI：933 项通过；fonts 示例：5 项通过。两仓库完整构建和严格 L2 门禁通过，相对本轮原始基线新增结果为 0；既有配置关闭项与格式／lint 存量保留，没有宣称零存量告警。
- 20 个新进程各执行 64 次强制 GC、变量重开与斜体绘制测试，全部正常退出；另覆盖映射释放、同路径字体替换、损坏／截断表、坐标越界、图集预算及淘汰后像素一致性。
- 与旧实现的 90 组独立画面对照，90 组度量一致、54 组图像逐像素一致。普通字形其余差异主要是预乘透明度的单通道 1 级舍入；3 组 Cascadia 默认字重斜体最大为 3 级、总墨量误差小于 0.01%。彩色字形保留真实位图尺寸，修复旧图集拉伸，与旧错误尺寸不要求像素一致。
- 保留独立的官方 `TTF_RenderText_Blended` 合成斜体像素验证。另用 fontTools 预生成静态实例，对 6 个字重 × 正／斜体 × 3 个缩放作 36 组对照；advance 相等，满足既有轮廓误差门禁。
- 原生桌面端到端覆盖 11 类场景、重复 3 轮：首帧显示、字体布局、文本编辑、滚动裁剪、故障恢复、数值边界等；增量／完整重绘差异为 0。六组 fonts 示例快照检查默认、斜体、大字号、角色、字宽和光学字号。
- CUI／SDL 文档检查分别通过 246／151 个文件，标记验证的仓颉文档程序分别编译通过 139／87 个。
- Windows 独立发布目录验收通过，移除开发库路径后仍能启动、绘制、唤醒与关闭；使用官方 SDL3_ttf 3.2.2，`native/` 已不存在。
- Linux／macOS 提供器和映射分支已完成宿主侧类型检查；**尚未进行对应系统的原生构建及实机运行验收**，不能据此宣布三平台正式发布。

官方 `SDL3_ttf.dll` 与 `libSDL3_ttf.dll` 的 SHA-256 均为 `9a3defa81cfb71a48256333f1a015ee72a9b7d82311891cdc87afcb9f23ec5a9`。

本机证据位于 `target/dev/font-migration-2026-09-07/`：`summary.json`、三组 `*-results.json`、`actual-startup-results.json`、`paired-summary.json`、`catalog-compatibility.json`、`oracle-comparison.json`、`gc-final-*.log`、`*-final-*.log` 和 `example-images/`。最终 20 个 GC 进程还各自运行了全部 15 个 `sdl.text` 用例，无跳过项。目录内保留测量脚本与旧版本备份；这些是本机验收产物，不随应用分发。独立发布记录为 `target/dev/release/windows-x86_64-delivery.json`。
