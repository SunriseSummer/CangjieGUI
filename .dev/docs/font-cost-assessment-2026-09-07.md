# 当前字体实现的性能评测（2026-09-07）

> 历史记录：本文保留当时的实现及测量结果。后续已移除原生扩展与补丁 DLL，取消隐式全量扫描；最新结果见[仓颉迁移与资源优化](font-memory-optimization-2026-09-07.md)，使用契约见[字体指南](../../docs/guide/how-to/fonts-and-typography.md)。

本次评测针对当前 CUI／CangjieSDL 生产实现及已部署的扩展版 SDL_ttf；不包含拟议的字体内存副本或自定义文本引擎。没有删除或关闭生产特性。

## 决策要点

- 启动的主要成本是全量系统字体目录构建。普通默认字体路径也会触发该流程；显式指定同一字体文件可以绕过它。
- 可变字体固定使用一个字重，或在少量离散字重间切换，缓存命中后与静态字体处于相同开销量级。
- 每帧改变连续字重／字宽会造成字体配置、测量和排版缓存失效，当前实现有明显 CPU 和内存成本。
- 原生轴设置本身为微秒级；不能把整条缓存失效路径的毫秒级耗时归因于轴插值计算。
- 系统目录里枚举 170 个命名实例约需 36 ms，占目录处理时间约 4.6%。删除这部分不能解决目前接近一秒的示例启动。

## 测试环境与口径

- Windows 11 Pro 10.0.26200；Intel Core Ultra 7 268V（8 核），Intel Arc 140V，驱动 32.0.101.6737，约 32 GiB RAM。
- Cangjie 1.0.5 cjnative，Windows x64，生产库与测试入口使用 `-O2`。使用仓库现有工具的高性能核心亲和策略；具体掩码见 `summary.json`。
- 每次条件在独立进程执行，串行运行，条件顺序按固定随机种子打乱。编译过程不计入测量，且测量期间不运行其它本任务构建。
- 原示例可执行文件重新构建，保留原窗口、VSync、自动超采样和默认参数，通过 Win32 枚举观察首个可见窗口；观察间隔请求为 1 ms，存在调度误差。窗口显示前已经由生产流程提交首帧；该指标不等于显示器实际发光时间。
- 可控启动入口复用原 `FontsModel`、视图和主题，关闭 VSync、`frameDelay=0`，在首帧提交并 show 后的下一次帧回调采样。此时间包括进程创建到仓颉入口的开销，可能比 show 本身稍晚。
- 启动条件各 5 次；渲染条件各 3 次、每次 620 帧，丢弃前 20 帧后将每条件 1800 个样本合并计算中位数与 P95。保留全部异常长帧，不删离群值。
- 本次是新进程启动、框架缓存为空的测量；操作系统文件缓存大多已预热，不代表重启电脑后的磁盘冷启动。
- CPU 为进程所有线程累计执行时间。帧 CPU 列为完整 620 帧的平均值，含首次加载；墙钟帧耗时含渲染提交／present，不代表纯 CPU 或精确 GPU 时间。
- 内存使用 Windows 进程 Private Bytes（私有提交量），不是全部实际驻留 RAM，也不是独立显存统计。数值包含 Cangjie 运行时、GUI 和驱动，字体影响应看同场景差值。工作集、峰值和关闭后结果保留在原始数据。
- 本机字体实验室测得实际文本栅格比例 2.25×2.25。压力测试显式指定的 1×／2×超采样仍叠加系统 DPI，不能按 100% DPI 的像素负载理解。

## 应用启动

原 `examples/fonts` 可执行文件：5 次首个可见窗口耗时 **982 ms**（中位数），范围 **926～1091 ms**；此时累计 CPU 时间中位数 922 ms，Private Bytes 约 168.9 MiB。

| 可控启动条件 | 启动中位数 ms | 范围 ms | CPU ms | Private MiB |
|---|---:|---:|---:|---:|
| 最小界面：默认字体解析 | 856.6 | 823.2～871.5 | 812.5 | 154.7 |
| 最小界面：默认解析＋磁盘元数据缓存 | 794.1 | 743.7～865.5 | 812.5 | 154.1 |
| 最小界面：直接指定相同字体文件 | 118.6 | 109.3～130.9 | 125.0 | 63.2 |
| 最小界面：窗口前主动构建目录 | 875.1 | 849.8～1033.8 | 812.5 | 153.5 |
| 字体实验室：当前模型／视图 | 922.8 | 914.0～995.7 | 921.9 | 168.7 |
| 字体实验室：启用磁盘元数据缓存 | 868.1 | 843.9～1056.9 | 843.8 | 165.9 |

默认解析和直接指定文件都实际使用 `C:/Windows/Fonts/msyh.ttc` 集合面 1。两者的界面、文本和窗口参数相同。差异约 738 ms，表明全量目录不是显示这段文字所必需。该差值包含目录及其后续分配影响，不能解释为某一条原生函数的耗时。

`Fonts.setMetadataCache` 缓存的是文件元数据；当前仍会执行平台枚举、目录遍历、名称关联和字体角色解析。它因此只能降低部分启动成本。

### 目录内部耗时

在一次性 SDK 副本中仅加入阶段计时，另跑有缓存／无缓存各 5 次，生产源码未改。该组与应用启动组独立采样，阶段中位数不要求精确相加等于另一组的总中位数。

本机共扫描 382 个文件，构建 222 个字体族、575 条面／实例记录；其中 21 个可变字体文件、170 个命名实例。平台提供器返回 462 条记录。

| 阶段 | 无磁盘缓存 ms | 有磁盘缓存 ms |
|---|---:|---:|
| 平台字体发现与记录转换 | 409.82 | 382.58 |
| 目录遍历＋字体元数据读取／缓存 | 160.12 | 112.34 |
| 字体族分组 | 0.56 | 0.72 |
| 平台记录与字体族名称关联 | 153.43 | 131.00 |
| 四类默认字体角色解析 | 53.23 | 52.77 |
| 目录构建总计 | 780.69 | 681.37 |

无缓存的扫描部分进一步分解：目录／路径处理约 65.36 ms，361 个静态字体文件检查约 50.58 ms，21 个可变字体文件检查约 42.32 ms。可变文件检查中，命名实例循环约 36.04 ms；这是嵌套计时，不能再次加到文件检查总时间中。

计时显示：启动优化首先应针对平台发现、目录懒加载、名称关联。当前名称关联存在平台记录与全部字体面嵌套遍历，且在循环中重复规范化路径。命名实例可改为按需展开，但其收益量级为几十毫秒；本次没有实际删除该特性，36 ms 不是删功能后的实测加速值。

## 真实字体实验室：持续刷新与字重变化

复用 `examples/fonts` 当前模型与界面，选择 Cascadia Code，默认字号 24；其余固定字重样本保留。固定模式使用 400；离散模式循环 400／600／700；连续模式循环 400～700、每帧增加 1。连续模式共跨越 301 个坐标，重复超过两轮。

| 模式 | 整帧中位数 ms | P95 ms | CPU ms/帧 | 620 帧后 Private MiB | 最后缓存配置数 |
|---|---:|---:|---:|---:|---:|
| 固定字重 | 0.740 | 2.993 | 0.932 | 151.2 | 15 |
| 三档字重 | 0.696 | 2.933 | 0.958 | 159.8 | 19 |
| 连续字重 | 5.892 | 6.993 | 6.502 | 205.6 | 64 |

连续模式比固定模式增加约 5.15 ms 的典型整帧耗时、54.4 MiB 的最终私有提交量。三档字重只在首次遇到相应配置时新增资源；本次整帧耗时略低于固定模式属于不同运行间波动，不意味着三档切换更快。

每次 620 帧的文字绘制调用同为 13640 次，固定／离散／连续的排版缓存未命中分别为 21／31／2216 次。这提供了比单纯帧率更直接的缓存失效证据。

上述模式都强制持续刷新。正常静止界面采用按需重绘，不能把这些数字换算成静止应用持续占用 CPU 的比例。

## 16 行混合文本压力场景

800×600 逻辑窗口；16 条固定文本，每帧各测量和绘制一次；字号 20；通过显式字体文件注册，使用微软雅黑 UI 回退。该路径与真实示例的已安装字体族路径不同，不能互相替代。

每进程均执行 9920 次测量和绘制。固定／三档模式的实际测量和排版计算分别只有 16／48 次；连续字重或字宽均为 9920 次。当前字体配置缓存最多保留 64 组；301 个连续字重、101 个字宽坐标循环会持续淘汰配置。

|---|---:|---:|---:|---:|---:|
| Consolas 静态固定 | 1× | 0.276 | 1.060 | 0.013 | 72.1 |
| Cascadia 可变固定 | 1× | 0.243 | 0.486 | 0.012 | 72.2 |
| Cascadia 三档 | 1× | 0.278 | 2.655 | 0.012 | 75.3 |

| Noto Sans SC 三档 | 1× | 0.262 | 1.066 | 0.012 | 75.3 |
| Noto Sans SC 连续 | 1× | 9.887 | 18.188 | 8.025 | 300.2 |
| Bahnschrift 连续字宽 | 1× | 9.827 | 11.737 | 8.595 | 232.6 |
| Consolas 静态固定 | 2× | 0.577 | 3.432 | 0.015 | 111.2 |
| Cascadia 可变固定 | 2× | 0.573 | 3.154 | 0.015 | 111.3 |

| Cascadia 连续 | 2× | 10.004 | 17.334 | 7.529 | 538.2 |
| Noto Sans SC 可变固定 | 2× | 0.585 | 3.219 | 0.013 | 111.7 |
| Noto Sans SC 三档 | 2× | 0.545 | 3.238 | 0.013 | 115.9 |

| Bahnschrift 连续字宽 | 2× | 10.055 | 18.582 | 8.627 | 409.4 |

稳定使用可变字体时，缓存命中后的开销与静态字体处于相同量级。字体不同，字形复杂度也不同，本表不应解读为对相同轮廓静态化前后的精确 A/B。

连续模式的测量阶段已经消耗约 7～9 ms，其中包含配置解析、字体打开、回退图创建与新文本测量。源码中，显式文件注册在新配置创建时会重新检查候选字体及样式文件；回退字体图也按配置独立构建。这些是实现成本，不是可变轮廓插值本身的必然成本。

在额外 2×超采样下，连续模式的私有提交量达到约 409～673 MiB，显著高于固定配置的约 111 MiB。这些都是当前扩展实现的实测，不涉及拟议的整字体副本。

部分压力运行中，配置计数到达 64 后 Private Bytes 仍继续增长；清理字体缓存或关闭窗口也不一定立即回到初始值。可能涉及分配器／GC、纹理图集与驱动保留，本次未完成堆对象归因，不能仅凭 Private Bytes 判定泄漏，也不能声称已经达到稳定上限。相关时间点数据保留在 JSON，适合作为后续内存剖析入口。

## 原生操作的成本量级

直接调用当前部署 DLL，字体大小 40 原生像素；只测未挂接文本时的轴设置。各操作预热 20 次，设置轴与热测量各采样 1000 次，打开／关闭各 300 次。由 Python ctypes 驱动，含计时与 FFI 包装开销，不是仓颉整帧基准；该实验用于区分微秒级操作与毫秒级配置重建。

| 字体 | 设置一次 wght μs | 打开＋关闭 μs | 打开＋设置＋关闭 μs | 热墨迹边界 μs |
|---|---:|---:|---:|---:|
| CascadiaCode.ttf | 4.90 | 173.90 | 179.85 | 0.90 |
| NotoSansSC-VF.ttf | 1.20 | 247.50 | 250.00 | 0.90 |

可变轴设置和墨迹边界没有表现出足以解释整帧增加数毫秒的直接成本。字体角色和字号样式的编码接口本身也不是目录重复工作或缓存淘汰的原因。

## 对特性取舍的建议

| 内容 | 本次证据支持的取舍 |
|---|---|
| 可变字体作为普通字体使用 | 可以保留；固定坐标下没有持续的明显额外负担 |
| 数值字重、少量离散字重 | 可以保留；三档配置可稳定命中缓存 |
| 任意轴坐标，但只偶尔改变 | 可以保留为高级能力；一次加载成本与持续每帧变化应区别对待 |
| 连续字重／字宽动画、每像素拖动都立即生成配置 | 当前代价明显，可优先限制、降低更新频率或取消此类交互；不必因此删除字体文件的可变格式支持 |
| 完整字体选择器与全部命名实例列表 | 有实际启动成本，适合进入字体选择页时再加载，命名实例按需展开 |
| 默认字体角色与系统字体名 | 使用方便；应优化解析流程，避免只为一个默认字体启动全量目录 |
| 共同基线、墨迹居中、正常粗斜体 | 没有测到值得为节省性能而放弃这些正确性／易用性能力的证据 |

以上建议不等于已经实现优化。尤其是以“命名实例耗时”估算删除收益、或以单字体热缓存结果外推所有脚本／字体，都应保留边界。

## 复现与证据

完整产物目录：`target/dev/font-cost-2026-09-07/`。

- `summary.json`：汇总、源文件哈希、生产 SDL_ttf 哈希、计时可执行文件哈希和环境。
- `actual-startup-results.json`：原字体示例 5 次启动。
- `startup-results.json`：40 次正式启动／目录条件及一次缓存准备运行。
- `render-results.json`：48 个压力进程，29760 帧。
- `lab-results.json`：9 个真实模型／视图进程，5580 帧。
- `trace-results.json`：仅增加计时的 SDK 副本，10 次目录归因运行。
- `native-cost-results.json`：部署 DLL 的原生操作采样。
- `logs/`：进程输出。原型试运行及采样结构修正前的结果未纳入最终统计；最终所有私有内存记录均经非零检查，实际示例使用独立 ctypes 结构交叉验证。
- `probe/`、`trace-probe/`、`sdk-trace/`：独立基准及只加计时的源码副本；`main-startup-render.exe` 保留启动／压力测量时的可执行文件。
