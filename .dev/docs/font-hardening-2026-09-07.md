# 字体与文本质量加固（2026-09-07）

本轮基于[字体仓颉迁移](font-memory-optimization-2026-09-07.md)完成后的代码，检视 CangjieSDL 的字体失效、资源归属、纹理合成，以及 CUI 的富文本排版和段落缓存。继续使用官方 SDL_ttf；未恢复 `native/`，未增加启动全量字体扫描，未改变应用公开接口签名。

## 修复与成本

| 问题 | 修复与约束 |
| --- | --- |
| SDL 渲染重置后字形图集仍持有失效内容，旧纹理包装对象未及时释放 | 重置时释放图集、整段文字纹理及超采样目标，按需重建；字体和存活测量会话保留。过期 Texture 禁止绘制，仍在所属 Renderer 存活时释放其拥有的 SDL 句柄。 |
| 注册的系统字体别名在同路径换文件并 reload 后仍报告旧元数据 | reload 统一使名称匹配、目录、持久／内存元数据失效。发现型 FontFamily 按版本重读原文件和集合面；文件暂时缺失后也能恢复，不扫描全目录。安装位置变化仍需重新 registerSystem。 |
| 测量会话可从错误线程关闭，破坏后续测量 | close 在修改状态和释放资源前检查 Renderer 线程归属；错误线程调用被拒绝，会话保持可用。 |
| 仅换行或零宽字符走旋转／斜体路径时异常或生成无用纹理 | 无绘制面积时直接跳过；真正的布局、分配、尺寸超限失败仍抛异常。 |
| 彩色 Emoji 在斜体／旋转路径中被文字颜色整体染色 | 单色文字保留原栅格化与跨颜色复用路径；含彩色字形时只给单色部分着色，保留彩色调色板，在合成时预乘 alpha，避免透明边缘插值染色。RGB 仅进入彩色纹理键，透明度仍可复用。 |
| RichText 把硬换行交给单行片段绘制，空行高度丢失 | 识别 LF、CRLF、CR、NEL、U+2028、U+2029，保留连续和末尾空行；跨样式片段的 CRLF 只换一行，保留原片段与链接身份。 |
| 段落 LRU 对空行只计字符串字节，低估保留内存 | 每行额外计入描述符／数组槽的估算成本，空行很多的布局同样受 4 MiB 预算约束；超预算结果可使用但不驻留。 |

彩色合成复用现有有界字形位图缓存，不另分配第二份整段 Surface。每个 Renderer 的字体配置仍限 24 个、字形图集 16 MiB、整段纹理 256 块／16 MiB，CPU 整段 Surface 限 16M 像素。缓存估算不等于进程内存或驱动显存；保留会话仍可能固定已淘汰字体。

重置时释放包装对象的依据是 SDL 区分纹理对象与后端资源：参见 [SDL 纹理销毁实现](https://github.com/libsdl-org/SDL/blob/release-3.4.0/src/render/SDL_render.c)和 [D3D 重置实现](https://github.com/libsdl-org/SDL/blob/release-3.4.0/src/render/direct3d/SDL_render_d3d.c)。本轮回归注入框架的重置入口，未模拟真实硬件设备失联。

## 验证记录

- 修改前构建与测试通过：CangjieSDL 206 项、CUI 933 项。先增加测试，复现上述缺陷后修复；未放宽原有单色像素对照断言。
- 修改后 CangjieSDL 212 项、CUI 936 项通过；包含 36 组独立静态轮廓／变量坐标验证、原有 60 组斜体 Surface 精确对照及 12 组旋转分块接缝对照。
- 90 组按修改前源码独立构建的图像与度量对照：90 组度量一致，81 组普通文字图像逐像素一致；9 组 Emoji 图像变化来自调色板恢复。另以红／蓝文字颜色绘制同一 Emoji，斜体与旋转结果分别完全一致。
- 桌面端到端 12 场景 × 3 轮通过。新增 RichText 用例在 1×／2× 超采样下，对照手工分行绘制的像素，并验证空行无链接命中、后续链接正确响应；保留启动、字体比例、编辑、滚动、恢复及增量绘制场景。
- 两层 L2 相对本轮源码基线均无新增发现。完整门禁保留项目既有 lint／格式提示及已说明的规则覆盖例外，不表示所有历史提示均已清零。
- 独立进程压力验证 30 次、共 360 个测试调用通过：20 × 15 个底层文本测试（含重 GC 与虚拟字体映射释放），10 × 6 个字体加固测试。
- 文档结构与 API 检查通过：CUI 247 页、CangjieSDL 151 页；139 + 87 个文档程序编译通过。开发工具自测、Windows 干净发布验证通过；fonts 的默认、斜体、40 fp、角色、字宽和光学字号 6 个场景截图已检查。

原始基线、失败复现、最终日志、源码对照图与验收清单保存在 `target/dev/font-hardening-2026-09-07/`。

## 开销复测

分别按本轮修改前源码快照和最终代码构建相同探针，交错运行 8 轮，每种场景／版本各 8 个独立进程，共 64 次。测试期间无并行构建；使用相同官方运行库、机器字体和 CPU 亲和设置。文件缓存未清空，因此这些数据不是机器冷启动结果。

| 指标（中位数） | 修改前 | 修改后 |
| --- | ---: | ---: |
| 最小默认字体应用首次显示 | 187.7 ms | 192.4 ms |
| fonts 页面首次显示 | 243.5 ms | 244.4 ms |
| fonts 首次显示私有内存 | 77.03 MiB | 77.09 MiB |
| 固定页面强制重绘间隔 | 0.649 ms | 0.643 ms |
| 固定页面 CPU／帧 | 0.882 ms | 0.895 ms |
| 连续字重预览重绘间隔 | 0.897 ms | 0.893 ms |
| 连续字重预览 CPU／帧 | 1.285 ms | 1.260 ms |
| 连续预览 620 帧后的私有内存 | 192.91 MiB | 191.62 MiB |

帧间隔剔除前 20 帧；CPU／帧按 620 帧期间的整个进程 CPU 时间计算，包含框架、GC 和驱动工作，不是仅字体函数的耗时。私有内存也不是字体缓存大小。初始 3 轮中的小幅启动／CPU 波动没有在 8 轮中扩大：默认启动增加约 4.7 ms，fonts 增加约 0.9 ms，未观察到明显资源放大。此对照用于检查本轮变化，不替代长期、多机器或跨平台性能门禁。
