# 字体／文本质量治理与编辑增强 · 2026-09-06

本轮先审查字体继承、缓存、原生边界及文本编辑链路，再增加可复现的失败测试。修改前 CUI 878 项、CangjieSDL 171 项测试全部通过；已有字体重构与配套 DLL 保留。

## 已确认并修复的问题

| 问题 | 原因与修复 |
| --- | --- |
| 显式字重／变量轴切换可能沿用旧换行 | 段落缓存只保存样式位，未保存显式数值字重和轴。补全键与字符串预算；350、400、wdth=90 的原始复现由一次计算变为三次独立计算 |
| 排版与编辑边界不一致 | 编辑按码点，旧排版规则仅近似 Mark、ZWJ、韩文连接。改为共享 Unicode 17 扩展字素状态机，移除旧 Mark 表，使用固定来源及摘要的数据和官方 766 组测试 |
| 同一版本号可能绘制旧文档行 | 行缓存忽略不同绑定或文本值的同版本号。增加值校验，同时规范 CRLF／CR 的绘制与行导航 |
| 一次选区替换发布中间空文本 | 先删除再插入触发两次正文写入。统一为一次替换，插入／删除导致相邻字素合并时重新确定合法光标位置 |
| 撤销恢复旧文档或修改只读内容 | 公共命令绕过只读保护，历史不知道应用已替换正文。集中处理只读、外部替换和撤销组；增加双栈合计 300 步／8 MiB 预算 |
| 剪切可能丢失未复制的文本 | 原生 C 字符串遇到 NUL 截断。SDK 在调用 SDL 前拒绝 NUL；控件确认复制成功且原选区未被宿主回调改变后才删除 |
| 粘贴、输入和 IME 行为不一致 | 统一换行和 NUL 校验；空／失败剪贴板保留选区。未聚焦输入不再清除其它控件的 IME，预编辑期间不删除已提交正文，提交独立成组 |

新增失败测试先复现了 7 项文本／字素问题、1 项显式字体缓存问题及原生剪贴板输入校验问题；失败日志保留在 `target/dev/text-quality/`。

## 编辑能力与代码结构

- TextField、TextArea 新增 `selectAll`、`selectRange`、`selectedText`、`replaceSelection`、`copy`、`cut`、`paste`、`canUndo`、`canRedo`，工具栏无需重新实现文本拼接和历史。
- `TextClipboard.system` 是默认后端；可注入读写函数，测试不改动用户系统剪贴板。读写失败、空数据、NUL 和回调重入均有负向覆盖。
- 支持 Shift 点击、按词段移动／删除；TextArea 保持水平像素列，长行横向跟随光标，绘制／选区／点击共享偏移。失焦选区保留淡色高亮。
- TextArea 补充文本值、聚焦和可编辑时 SetValue 语义；两个控件的语义写入使用相同校验与历史路径。
- 按职责拆出编辑命令、剪贴板、字素缓存、行缓存、导航几何与绘制；控件保留布局和事件路由。绘制裁剪通过 finally 恢复，避免异常污染后续绘制。
- 更新 editor 示例，展示真实编辑命令、只读和操作结果；保留原有菜单教学目的。

## 使用与后续

已有构造调用保持兼容，新增可选 `clipboard` 参数。偏移仍是 UTF-8 字节，但吸附到完整字素；只读 Ctrl+X 现在与公开 `cut` 一致，不修改正文也不代替复制。需要复制使用 Ctrl+C／`copy()`。

绑定正文的直接赋值会清除旧历史；应用的可撤销编辑使用 `replaceSelection`。具体代码见 [文本编辑指南](../../docs/guide/how-to/text-editing.md) 和 [editor 示例](../../examples/editor/README.md)。

仍需推进软换行、完整 bidi 与共享 shaping 几何、IME 预编辑内部布局、原生文本范围无障碍、默认右键编辑菜单、静止指针越界选择滚动及 Linux/macOS 原生剪贴板／IME 实机矩阵，已写入 [待办](../../.todo/todo.md)。
