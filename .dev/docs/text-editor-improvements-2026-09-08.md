# 文本编辑控件增强与验收

本轮面向普通桌面表单、备注与中等规模纯文本编辑，补齐编辑器外观、软换行、输入法预编辑和按需 Emoji 后备。实现仍全部位于 CangjieGUI／CangjieSDL 的仓颉代码中，使用官方 SDL_ttf 3.2.2，不恢复 native 补丁或启动时全量字体枚举。

后续已完成首次 Emoji 内存归因、原生字体复用与缓存优化，见[资源实测与优化](emoji-resource-optimization-2026-09-08.md)。下文性能数字保留为当时版本的历史基线。

## 能力取舍

对照 [Qt QLineEdit](https://doc.qt.io/qt-6/qlineedit.html)、[QPlainTextEdit](https://doc.qt.io/qt-6/qplaintextedit.html) 的输入、选择、撤销、只读、占位、对齐和换行能力，以及 [Flutter StrutStyle](https://api.flutter.dev/flutter/painting/StrutStyle-class.html) 的最小行度量思想，本轮优先统一所有编辑路径使用的几何，保留现有绑定与编辑命令。

| 能力 | 本轮结果 |
| --- | --- |
| 字体／字号／字重／倾斜 | 继续通过 TextStyle 继承，与原有 FontWeight／变量轴兼容。 |
| 行高／内边距／对齐／颜色／背景 | 新增共用 TextInputStyle；最小行高不低于自然字体高度，选区、光标、命中与滚动同步。 |
| 单行提示与提交 | 新增 placeholder／onSubmit；预编辑 Enter 不触发表单提交。 |
| 多行软换行 | 按词段／字素边界排可视行；Home／End、上下键、PageUp／PageDown 与 Shift 选择共用布局。 |
| 选择／复制／剪切／粘贴／撤销 | 延续统一命令与失败保护；收拢键盘命令分派，避免两类编辑控件行为分叉。 |
| 输入法 | 预编辑替换选区后重新布局；按原生内部选区定位光标；只读不发布输入法锚点。 |
| Emoji | 🎉 等缺字按需补入平台 Emoji 字体，保留彩色调色板；编辑按完整扩展字素处理。 |
| 密码、验证、默认右键菜单、完整 bidi | 仍为独立后续能力，没有以部分实现代替完整契约。 |

## 缺陷与实现

1. **Emoji 显示缺字符框**：系统 UI 字体缺字时原后备链没有 Emoji 字体。新实现仅在字符串出现候选码点时，定向查询 Windows Segoe UI Emoji、Linux Noto Color Emoji 等或 macOS Apple Color Emoji，追加到后备链。普通文本不执行该查询。查询缓存上限 256 条／128 KiB；含 Emoji 的不可变字体配置与普通配置共享原有 24 配置上限，存活测量会话不会被淘汰破坏。
2. **预编辑覆盖正文、光标总在末尾**：引入独立显示映射，视觉文本为“选区前正文 + 预编辑 + 选区后正文”，原始绑定与撤销历史保持到提交时才变化。按码点转换内部选区到 UTF-8 字节，不把 CRLF 或四字节 Emoji 的偏移混为一谈。
3. **只读输入框误激活输入法**：只读状态清除本控件预编辑／输入锚点，保持选择、复制与文本鼠标指针。滚轮把可编辑光标移出视口时，候选锚点钳制到视口边缘，保持输入会话。
4. **布局与编辑坐标分散**：TextEditorLayout 保存硬换行和软换行可视行，TextEditorView 统一行位置、对齐、选区、光标、命中和候选锚点。缓存按文本、字体环境和换行宽度失效；软换行不删除空格、不插入换行、不拆开字素。淘汰旧绘制／行缓存／线性行号辅助路径，保留原回归断言并迁移到新几何。
5. **样式扩展易发生大字号重叠或点击错行**：TextInputStyle 统一内边距与最小行高。显式行高把文字置于行中，选区覆盖完整行高；TextField 自然高度包含行高与上下内边距。负值、非有限长度、零行高／光标宽度会被拒绝。
6. **切换过程回归**：键盘操作仍即时更新外部滚动状态；软换行启用后在事件处理前清除旧横向位移，避免首次点击命中错误。光标移动重启闪烁相位，时钟重置与溢出边界保持安全。
7. **选中文字重复叠色**：独立像素用例复现先画普通文字、再覆盖半透明选中文字产生 7,143 个不同像素。改为对选区及两侧分别裁剪整行绘制，保持 shaping 结果，避免重复合成；同时覆盖彩色 Emoji。

公开构造方式保持兼容。新增 `.style(...)`、`.placeholder(...)`、TextField `.onSubmit(...)`、TextArea `.wrap(value: ...)`，根包导出 TextInputStyle。SDK 新增 FontRole.emoji 和 Key.PageUp／PageDown；使用 `RawScancode(75/78)` 或穷尽 Key 匹配的调用者需要迁移。

最后使用完整工作树指纹执行 Windows 独立运行库发布验证；结果和源码／运行库摘要以本轮 `acceptance.json`、`release-results.json` 为准。该验证使用已安装的系统字体，不替代干净机器及其它平台验收。

性能在 Windows 同一机器上交错运行修复前／后源码构建，各场景 6 次，共 72 个独立进程；测量期间没有并行编译。以下为中位数，进程私有内存包含运行时、驱动、字体及渲染缓存。

| 启动场景 | 修复前耗时 | 修复后耗时 | 修复前 / 后私有内存 |
| --- | ---: | ---: | ---: |
| 普通 UI | 219.1 ms | 197.9 ms | 58.13 / 58.14 MiB |
| 含 Emoji 的同一文本 | 221.9 ms | 238.7 ms | 58.11 / 74.42 MiB |
| fonts 实验室 | 282.7 ms | 283.4 ms | 77.25 / 77.17 MiB |

普通启动和 fonts 示例的内存基本不变。Emoji 样本修复后额外约 **16.3 MiB** 私有内存，耗时中位数增加约 **16.8 ms**；修复前的 Emoji 图形不完整，增量包含新增字体和字形渲染成本。普通启动自身也有较大调度／文件缓存波动，不把其约 21 ms 的下降解释为框架加速。此处是进程级观测，尚未分解原生字体、校准字体和驱动的具体占比。

| 编辑场景 | 修复前首帧 / 暖滚动帧 | 修复后首帧 / 暖滚动帧 |
| --- | ---: | ---: |
| 1,000 硬行，不软换行 | 14.52 / 0.142 ms | 17.64 / 0.141 ms |
| 10,000 硬行，不软换行 | 72.64 / 0.156 ms | 79.26 / 0.161 ms |
| 1,000 硬行，启用软换行 | 原先无此功能 | 35.65 / 0.078 ms |
| 10,000 硬行，启用软换行 | 原先无此功能 | 240.22 / 0.080 ms |

文档分别为 86,890／878,890 字节；使用真实 SDL 后端、400×300 逻辑视口、强制完整组件阶段和 202 帧滚动，暖帧排除前 20 帧。1,000／10,000 行非换行场景的最终私有内存约 143.88／182.06 MiB，修复前为 143.89／181.23 MiB。软换行为 111.88／204.79 MiB；这些数值是进程占用，不是行索引或字体缓存独占的内存。

10,000 行软换行首排约 240 ms；后续滚动复用布局后约 0.080 ms。本轮测量首排与滚动，尚未将编辑后的整篇重排改为增量，也未宣称超大文档无延迟。字体共享与内存归因、大文档增量索引已保留在待办中。


## 使用与后续限制

完整代码见[文本编辑指南](../../docs/guide/how-to/text-editing.md)、[TextInputStyle](../../docs/api/cui/text/TextInputStyle.md) 和 [editor 示例](../../examples/editor/README.md)。示例提供自动换行、宽松行距、占位提示、Emoji 混排和编辑工具栏。

自动后备以补缺为目的，保留应用字体与显式后备优先级。[SDL_ttf 3.2.2 的回退实现](https://github.com/libsdl-org/SDL_ttf/blob/release-3.2.2/src/SDL_ttf.c) 按缺失字形区段补排；含已有字形或默认忽略字符的 Emoji 组合可能被拆为多个图形。实测 🎉 彩色绘制正常，但默认混排中的 👩🏽‍💻 仍可能显示为多个组成图形；旗帜和 VS15／VS16 也依赖字体及回退分段。这与“不拆字素地选择／删除”是两项独立能力，后续需要簇级字体选择与共享 shaping 布局，不能仅靠多加后备字体保证。

当前不提供段落级 bidi／RTL 编辑、跨样式统一 shaping、密码遮掩、统一表单验证、默认右键编辑菜单、横向滚动条、静止指针越界持续选区滚动或超大文档增量编辑。完整目录查询仍是显式同步操作。

原生绘制与自动化运行在 Windows；注入 IME 事件不等于验证所有实际输入法候选窗口。Linux／macOS 字体提供器和 Emoji 候选已实现，但本机不能代替相应平台构建、渲染与输入法实机验收。
